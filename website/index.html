Why a runtime?

A research project outlives a chat window.

Long-running research needs durable state, typed evidence, explicit decision boundaries, and recovery after interruption. ResearchOS treats those requirements as runtime contracts, not as instructions hidden inside a long prompt.

Four core research capabilities

ResearchOS compiles the transitions where research usually becomes fragile.

Instead of asking one agent to do everything, each transition produces inspectable artifacts, bounded authority, and a clear handoff to the next stage.

01 · Research Evidence

Compile literature into a research space.

ResearchOS verifies and prioritizes papers, records reading coverage, turns each retained work into structured evidence, then compares mechanisms, designs, results, tensions, and boundary conditions across papers.

  • Paper cards preserve mechanism, design rationale, evidence level, and support boundaries.
  • Cross-paper synthesis surfaces contribution spaces, conflicts, bridge transfers, and open questions.
  • An optional survey branch can turn the evidence base into a taxonomy-driven, audited survey manuscript.

02 · Idea Evolution

Evolve a portfolio before selecting a direction.

T4 starts from evidence routing and research opportunities, creates a population of candidates through multiple routes, separates generation from scoring, and evolves directions through bounded mutation and compatibility-gated crossover.

  • Generators propose; blinded scorers evaluate; evolvers create bounded children.
  • Parent and child candidates are independently re-evaluated before survival.
  • The researcher selects at Gate1; novelty/collision audit happens before formal research-plan authority.

03 · Execution Compilation

Compile an accepted research plan into an execution contract.

ResearchOS does not silently become the experiment runner. It compiles the accepted T4.5 package into a constrained handoff, specializes a project-specific Skill suite, and delegates implementation and experimentation to an external executor.

  • Task, mechanism, required baselines, evaluation protocol, resource limits, and claim boundaries are carried forward.
  • Codex CLI, Claude Code, or a human executor can implement and iterate inside the accepted contract.
  • Results return through a validated Writer Handoff rather than an informal summary.

04 · Evidence-to-Manuscript

Route evidence into a defensible paper.

T8 builds resource and alignment indexes before drafting. Evidence is routed by section, then the manuscript passes review, revision, and claim audit before T9 assembles and compiles the submission bundle.

  • Literature evidence, accepted experiment facts, figures, tables, and claim boundaries remain distinguishable inputs.
  • Each section gets the evidence it needs rather than a flat context dump.
  • The writer organizes the narrative; it cannot manufacture evidence or expand claim authority.

Quick start

Start with a workspace, not a chat.

Configure the model connection, create one project workspace, then let the state machine advance the governed pipeline.

Quick Start ↗ Pipeline ↗ External Executor ↗ 中文文档 ↗
Terminal 
# Configure the model connection
python -m researchos.cli configure-llm

# Create one durable project workspace
python -m researchos.cli init-workspace \
  --workspace ./workspace/project-a \
  --project-id project-a \
  --topic "your research topic"

# Start the governed pipeline
python -m researchos.cli run \
  --workspace ./workspace/project-a
